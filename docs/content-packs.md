# Content packs

A content pack holds everything event-specific: the app name and copy values, the palette, brand art, the sites and the item photos. The code never names an event; it reads the active pack.

## Active pack

- `pack/pack.json` and `pack/brand/*`: sources of the active pack (brand PNGs are not bundled as-is).
- Bundled copies, written by `tool/apply_pack.dart`: `lib/config/pack.g.dart`, `assets/brand/logo.png`, `assets/sites/**`, `assets/items/*`, `android/app/src/main/res/drawable-*/ic_stat_notify.png`, and the launcher and splash images (generated by `flutter_launcher_icons` and `flutter_native_splash` from `pack/brand`).

The repo ships a demo pack: one site, Champ de Mars in Paris, with generated pixel-art branding and freely licensed photos from Wikimedia Commons (credits in `assets/items/CREDITS.md`).

## Layout

```
pack.json
brand/icon.png             1024x1024 launcher icon, full bleed, opaque
brand/icon_foreground.png  1024x1024 adaptive-icon foreground, transparent, art inside the central 66%
brand/splash.png           768x768 splash glyph, transparent
brand/logo.png             in-app logo, transparent, square (256x256 pixel art, nearest-neighbour scaled)
brand/ic_stat_notify.png   96x96 notification glyph, white on transparent (scaled to 24/36/48/72/96 px for mdpi..xxxhdpi)
sites/index.json           {"sites": ["<id>", ...]}
sites/<id>/site.json       id, name, center, radiusMeters, bounds, optional boundary
sites/<id>/tilemap.json    generated by tool/mapgen
sites/<id>/items.json      hidden items (title, text, image, lat, lng, radiusMeters)
items/*.webp               item photos, max 960 px
items/CREDITS.md           optional photo credits: a Markdown table, one row per photo, first column `File` (the webp name)
```

Item `image` paths point at the bundled location, `assets/items/<file>.webp`.

When `items/CREDITS.md` exists, each table row becomes an "Item photos" entry on the in-app Licenses page (`lib/config/licenses.dart`), and `test/content` checks that every item photo has a row. Ship it when the photos need attribution (CC BY, CC BY-SA).

## pack.json

```json
{
  "appName": "FogCatcher",
  "tagline": "Walk to clear the fog. Find what it hides.",
  "eventLine": "Champ de Mars · Demo pack",
  "eventEnd": "2099-12-31T23:59:59Z",
  "defaultSiteId": "champ_de_mars",
  "palette": {
    "primary": "#29ADFF",
    "primaryDeep": "#065AB5",
    "ink": "#1D2B53",
    "paper": "#FFF1E8",
    "accent": "#FFA300",
    "alert": "#FF004D",
    "shade": "#7E2553",
    "highlight": "#FF77A8"
  }
}
```

| Key | Use |
|---|---|
| `appName` | App name in copy (ARB `{appName}` placeholders) and the Android launcher label (`android/app/build.gradle.kts` reads `pack/pack.json` into `manifestPlaceholders["appLabel"]`). |
| `tagline` | One-line pitch (exposed as `packTagline`). |
| `eventLine` | Line shown on the score card. |
| `eventEnd` | UTC ISO-8601 instant; after it the game phase is ended and the app shows the score. |
| `defaultSiteId` | Site used unless another is forced; must be listed in `sites/index.json`. |
| `palette` | `#RRGGBB` colours, generated into `AppColors`. `ink` is also the launcher icon and splash background. |

## site.json

`boundary` (optional, an OSM ref string `"way/<id>"` or `"relation/<id>"`) makes that way or relation the playable boundary instead of the `radiusMeters` circle. `tool/new_site.dart --boundary <type>/<id>` sets it. The demo site uses `"boundary": "way/4208595"`.

## Applying a pack

```sh
dart run tool/apply_pack.dart packs/<name>   # copy a pack in and regenerate
dart run tool/apply_pack.dart                # re-apply pack/ after editing it
dart run tool/apply_pack.dart --check        # exit 1 if lib/config/pack.g.dart is stale (CI)
```

Applying a pack other than `pack/` replaces `pack/`, `assets/sites/` and `assets/items/`. It also rewrites the site entries in `pubspec.yaml` and the icon and splash colours. Run `scripts/ci-local.sh` afterwards.

To add a site to the active pack, use `tool/new_site.dart` (see the README).

## Keeping a pack private

Photos and event details usually must not be public. Two options:

- Put the pack in `packs/<name>/` inside this checkout. `packs/` is git-ignored, so nothing in it is committed.
- Keep the pack in a separate private repo and pass its path: `dart run tool/apply_pack.dart ../my-pack`.

Applying a private pack overwrites the tracked demo files (`pack/`, `assets/`, generated icons, `pack.g.dart`, `pubspec.yaml`). Do not commit those changes to a public repo. Restore the demo files with `git restore` before committing, or keep that build on a private fork.
